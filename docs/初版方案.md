## 一、需求分析

### 1.1 目标用户与核心场景

音游玩家（如《Project SEKAI》《BanG Dream!》等）的练习需求与普通视频播放有本质区别——他们需要反复观看特定难点段落，从视觉和操作两个维度拆解谱面。核心使用场景是：用户将手元或谱面确认视频导入App，通过**精确控制播放节奏**来研究指法和节奏。

### 1.2 功能需求清单

| 需求类别 | 具体功能 | 优先级 |
|---------|---------|--------|
| 视频源 | 从本地存储选择视频文件（mp4、mov等主流格式） | P0 |
| 播放控制 | 播放/暂停、进度拖拽 | P0 |
| 倍速播放 | 支持0.25x~2.0x多档变速，音调同步调整（不变调） | P0 |
| 选区循环 | 用户可设置A/B两个时间点，播放器在区间内无限循环 | P0 |
| 精细定位 | 逐帧前进/后退、按0.1秒步进 | P1 |
| 书签/标记 | 在时间线上添加标记点，便于快速跳转 | P2 |
| 播放历史 | 自动记录上次播放位置和循环选区 | P2 |

### 1.3 非功能需求

- **低延迟响应**：变速和跳转操作需在100ms内响应，音游练习对操作反馈敏感
- **音视频同步**：变速播放时必须保持音画同步，不能出现声画错位
- **内存管理**：避免加载大视频时内存溢出，支持流畅播放1080p视频
- **电池与发热**：优化解码策略，避免长时间练习导致设备过热

## 二、技术选型建议

| 组件 | 推荐方案 | 理由 |
|------|---------|------|
| 播放引擎 | **Media3 ExoPlayer** | Google官方维护，原生支持变速播放（`setPlaybackSpeed`）和循环（`LoopingMediaSource`），API设计灵活，是Android音视频播放的事实标准 |
| UI框架 | Jetpack Compose 或 XML + Material Design | 需要自定义播放控制面板（倍速按钮、选区设置UI），Compose在自定义组件上更高效 |
| 架构 | MVVM + Repository 模式 | 将播放器状态与UI解耦，便于管理复杂播放状态 |
| 本地存储 | MediaStore API（Android 10+） | 用于访问本地视频文件，符合现代Android存储规范 |

**备选方案**：可评估 wlmedia SDK，它封装了变速变调、循环播放等功能，集成成本较低，但生态和文档成熟度不如ExoPlayer。

## 三、核心功能实现方案

### 3.1 变速播放

ExoPlayer 通过 `Player.setPlaybackSpeed(float speed)` 实现变速，官方接口支持 `(0, 2]` 范围的速率调节。关键实现细节：

- **音调处理**：ExoPlayer 默认变速时会保持音调不变（通过 TimeStretching 音频处理器），这对于音游玩家听辨节奏至关重要
- **UI设计**：建议提供预设档位（0.25x、0.5x、0.75x、1.0x、1.25x、1.5x、2.0x），同时支持滑块微调

### 3.2 选区循环播放

这是本App的核心差异化功能，有两种实现路径：

**方案一：基于 LoopingMediaSource（推荐）**
```kotlin
// 通过ConcatenatingMediaSource实现精确区间循环
val clipSource = ClippingMediaSource(
    originalSource,
    startPositionUs,
    endPositionUs
)
val loopingSource = LoopingMediaSource(clipSource)
player.setMediaSource(loopingSource)
```
- **优势**：由播放器底层处理，无缝衔接，无卡顿
- **注意**：`ClippingMediaSource` 需要媒体支持精确Seek，部分格式可能有误差

**方案二：监听位置手动Seek**
```kotlin
player.addListener(object : Player.Listener {
    override fun onPositionDiscontinuity(reason: Int) {
        if (player.currentPosition >= endPos) {
            player.seekTo(startPos)
        }
    }
})
```
- 适用于精度要求不高的场景，实现简单但可能存在跳转延迟

### 3.3 视频选择与权限

- Android 13+ 需申请 `READ_MEDIA_VIDEO` 权限
- 使用系统文件选择器（`Intent.ACTION_OPEN_DOCUMENT`）让用户选视频，避免直接文件访问的兼容性问题

## 六、风险与注意事项

1. **视频格式兼容性**：ExoPlayer虽支持广泛，但部分编码格式（如某些厂商的HEVC）可能需要软解降级，需做好异常处理
2. **循环跳转精度**：`ClippingMediaSource` 的Seek精度依赖视频关键帧间隔，H.264通常间隔250ms左右，对于音游精细练习可能不足，可考虑配合逐帧步进功能补充
3. **后台播放**：需处理音频焦点的获取与释放，避免与其他音乐App冲突
4. **大视频加载**：建议使用 `ProgressiveMediaSource` 实现边下边播，避免等待完整加载
